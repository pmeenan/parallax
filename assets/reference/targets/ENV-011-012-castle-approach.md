v1's buildings between foreground fields and castle depict village, but no coastal
extension/port is established. Castle002 selected silhouette/moat, not a complete
coastal master layout. Its crop omits coast too; matching it does not validate this
vista. The blanket initial pass was insufficient for ENV-011 geographic purpose.
Do not use v1 as an approved world-layout target.

Current district-1.data.ts zones place castle/moat centrally, village roughly
z=-768..640 outside moat, fields z=-1536..-640 and shore z<-1536, with forest
z>=768. Thus a field-to-castle view can put coast behind camera; coast absence alone
is not a contradiction. However this greybox's field band separates village from
shore, leaving the creative shore-village requirement and later substantial port
connection unresolved. This is a pre-existing design/greybox/art reconciliation
need, not authorization to change coordinates silently. Gate B also differs from
A/002 in gate placement; retain as local appearance only pending shared layout.

Next geography work should establish one reviewable orientation/site plan linking
castle/moat, continuous village/port frontage, inland agricultural approaches and
forest, reconcile it with authored data, and fix camera locations before regenerating
wide vistas. Any resulting load-bearing layout change needs the ordinary recorded
decision and affected-doc update; no world data changed in this audit.
